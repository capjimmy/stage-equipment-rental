핵심 실행 원칙

1. 공급 우선 (Supply First)

수요 없이 공급 확보 → "볼거리 있는 플랫폼"을 만들어야 수요자가 온다. 처음 4주는 영업/섭외에 80% 집중.

2. 직접 거래 유도

초기엔 플랫폼 바깥 거래 방지보다 "플랫폼 통해 거래하면 편하다"는 경험 제공이 중요. 지나친 통제 금지.

3. 신뢰 구축 최우선

첫 거래 + 첫 정산이 가장 중요한 마일스톤. 1건이라도 성공 사례를 만들어 레퍼런스화.

4. 문제 발생 = 정책 수립 기회

파손, 분실, 지연 등 문제가 생기면 즉시 정책화. 미리 모든 걸 정하기보다 실제 케이스 기반으로 개선.

# 질문 답변
1 수수료가 50%면 너무 높은 거 아닌가요? 저희가 마케팅, 고객 확보, 결제, CS를 모두 담당합니다. 대표님은 상품만 준비하시면 됩니다. 기존 고객은 그대로 유지하시고, 저희를 통해 추가 고객만 받으시면 50%가 순수익입니다. 첫 달은 40%만 받습니다.
2 기존 고객이 플랫폼으로 오면 손해 아닌가요? 기존 고객은 기존 방식 그대로 하시면 됩니다. 플랫폼은 '신규 고객 채널'로만 활용하세요. 기존 고객에게는 굳이 플랫폼을 알릴 필요 없습니다.
3 정산은 언제, 어떻게 되나요? 매월 1~말일 거래분을 익월 15일에 정산합니다. 정산서를 먼저 보내드리고, 확인 후 계좌이체 + 세금계산서 발행됩니다. 대시보드에서 실시간 매출도 확인 가능합니다.
4 물건이 파손되면 누가 책임지나요? 수요자(빌린 사람) 책임입니다. 저희 약관과 예약 과정에서 파손 시 배상 조건을 명확히 고지합니다. 고가 품목은 보증금을 미리 받고, 파손 시 차감 후 정산합니다.
5 상품 등록이 어렵지 않나요? 저희가 다 해드립니다. 엑셀로 목록만 주시면 일괄 등록하고, 원하시면 방문 촬영도 무료로 해드립니다. 이후 수정은 관리자 페이지에서 쉽게 가능합니다.
6 예약이 겹치면 어떻게 하나요? 저희 시스템이 자동으로 재고/기간 체크합니다. 이미 예약된 기간은 다른 사람이 예약할 수 없어요. 더블부킹 걱정 없습니다.
7 거래가 없으면 비용이 드나요? 아니요, 거래 성사 시에만 수수료가 발생합니다. 입점비, 월회비, 광고비 전부 없습니다. 리스크 제로입니다.
8 배송은 누가 하나요? 배송은 기본적으로 수요자가 선택/부담합니다. 직거래, 퀵, 택배, 화물 옵션 중 선택하고, 비용도 수요자가 냅니다. 대표님은 포장만 해주시면 됩니다.
9 가격은 제가 정하나요? 네, 100% 대표님이 정합니다. 일일/주간/월간 가격, 세트 할인 등 자유롭게 설정 가능합니다. 시장 가격 참고 데이터도 제공해 드릴 수 있어요.
10 언제든 그만둘 수 있나요? 네, 계약 해지는 30일 전 통보로 가능합니다. 진행 중인 예약만 완료되면 위약금 없이 해지됩니다.
11 다른 플랫폼에도 등록해도 되나요? 네, 독점 계약 아닙니다. 다만 재고/일정 관리를 위해 예약 현황을 저희와 동기화해 주셔야 합니다.
12 고객 응대는 누가 하나요? 기본 문의는 저희 CS팀이 1차 대응합니다. 상품 상세 문의나 특수 요청은 대표님께 연결해 드립니다.
13 계약서가 복잡하지 않나요? 2페이지 분량의 간단한 계약서입니다. 핵심은 수수료율, 정산 주기, 책임 범위 3가지뿐이에요. 전자 서명으로 5분이면 완료됩니다.
14 어떤 상품을 올려야 하나요? 대표님이 렌탈 가능한 모든 상품이요. 의상, 소품, 장비 다 됩니다. 수요가 많은 품목(시대별 의상, 무대 조명, 가구 등) 위주로 먼저 올리시는 것도 좋습니다.
15 지금 바로 시작해야 하나요? 지금 입점하시면 첫 달 수수료 40% 혜택과 무료 촬영 서비스를 드립니다. 2월 공연 시즌 전에 등록하시면 노출 효과가 더 좋습니다.

🔒 재고 충돌 방지 규칙

규칙 설명 구현 방식
1. 수량 체크 예약 요청 시 해당 기간에 가용 수량 확인 availableQty = totalQty - reservedQty(period)
availableQty >= requestQty 이어야 예약 가능
2. 버퍼 기간 예약 간 정비/세탁을 위한 버퍼 예약 종료일 + bufferDays 이후부터 다음 예약 가능
예: bufferDays=1이면 2/10 반납 → 2/12부터 가능
3. 동시 요청 처리 같은 시간에 동일 상품 요청 시 Firestore Transaction 사용
먼저 commit된 요청만 성공
실패 시 "이미 예약됨" 안내
4. 예약 잠금 결제 진행 중 임시 잠금 결제 시작 시 15분간 임시 예약(PENDING)
결제 미완료 시 자동 해제
임시 예약도 수량에서 차감
5. 연체 처리 반납 지연 시 다음 예약 보호 반납일 D+1 알림
D+3까지 미반납 시 다음 예약자에게 공지
D+3 초과 시 분실 처리 고려

// 특정 기간의 가용 수량 계산 function getAvailableQuantity(productId, startDate, endDate) { const product = getProduct(productId); const totalQty = product.quantity; const bufferDays = product.bufferDays || 0; // 해당 기간과 겹치는 예약 조회 const overlappingReservations = getReservations({ productId: productId, status: ['PENDING', 'CONFIRMED', 'SHIPPED', 'IN_USE'], // 예약 기간 + 버퍼가 요청 기간과 겹치는지 dateRange: { start: addDays(startDate, -bufferDays), end: addDays(endDate, bufferDays) } }); // 겹치는 각 날짜별로 예약된 수량 계산 const reservedByDate = {}; for (const rsv of overlappingReservations) { const effectiveStart = rsv.startDate; const effectiveEnd = addDays(rsv.endDate, bufferDays); for (let d = effectiveStart; d <= effectiveEnd; d = addDays(d, 1)) { reservedByDate[d] = (reservedByDate[d] || 0) + rsv.quantity; } } // 요청 기간 중 최대 예약 수량 찾기 let maxReserved = 0; for (let d = startDate; d <= endDate; d = addDays(d, 1)) { maxReserved = Math.max(maxReserved, reservedByDate[d] || 0); } return totalQty - maxReserved; } // 예약 가능 여부 확인 function canReserve(productId, startDate, endDate, requestQty) { const available = getAvailableQuantity(productId, startDate, endDate); return available >= requestQty; }

항목 계산식 예시 비고
총 거래액 렌탈비 + 배송비 100,000 + 5,000 = 105,000원 VAT 포함
플랫폼 수수료 렌탈비 × 수수료율 (50%) 100,000 × 50% = 50,000원 렌탈비만 기준
공급자 정산액 렌탈비 - 수수료 + 배송비 100,000 - 50,000 + 5,000 = 55,000원 배송비는 전액 전달
환불 차감 환불금 × 환불 정책 100% 환불: -55,000원 수수료도 환불
파손비 추가 파손비 × (1 - 수수료율) 20,000 × 50% = 10,000원 파손비도 수수료
연체료 추가 연체료 × (1 - 수수료율) 10,000 × 50% = 5,000원 연체료도 수수료
최종 정산액 기본 정산 - 환불 + 파손비 + 연체료 55,000 - 0 + 10,000 + 5,000 = 70,000원
